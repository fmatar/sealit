# CAP-04: Single-Path Measured Quality Gate (Coverage, Mutation & Secret Scan)

- **Capability ID**: `CAP-04`
- **Governing Modules**: `.agent/scripts/lib/parsers.mjs` (Ring 1), `.agent/scripts/lib/session.mjs` (Ring 1), `.agent/scripts/lib/measure.mjs` (Ring 2), `.agent/scripts/lib/guard.mjs` (Ring 2)
- **Enforced Invariants**: `INV-02`, `INV-04`

## 1. Inputs
- Monotonic effective policy (`loadEffectivePolicy` per `ADR-021`): module commands (`head`, with changes raising `GATE_POLICY_DRIFT`), monotonic floors (`max(base, head)` for `diffCoverage` and `mutationScore`, `base || head` for `archlens.enabled`, base-only mutant `exemptions` with head additions surfaced as `pendingExemptions`, and monotonic `stryker.config.json` `mutate` globs; `policySource: 'bootstrap'` when base has no `sealit-config.json`).
- Commit-object `ChangeSet` (`diff-tree -r -z --raw --no-renames` and `diff-tree -r -p -U0 -M` via `ADR-020`; `diff-index` for advisory `coverage`/`mutation` commands) against effective base branch and real coverage/mutation reports on disk (`lcov.info`, `jacoco.xml`, `coverage.xml`, `cover.out`, summary-only `coverage-summary.json`/`jacoco.csv`, Stryker `mutation.json`, PITest `mutations.xml`, `mutants.out/outcomes.json`, `.mutmut-results.{json,txt}`, `go-mutesting.txt`).

## 2. Domain Rules
1. **Clean Commit-Object Gate & Engine-Bound Cache (`ADR-020`, `ADR-028`)**: `runGate` refuses dirty working trees upfront (`DIRTY_WORKING_TREE: commit or stash before gating`), evaluates two deterministic modes (`docs-only` and `code`) strictly from committed trees, keys `gate-cache.json` (written under `withFileLock`) on `KERNEL_DIGEST`, effective `modulePolicy`, `baseSha`, `headSha`, and `treeSha`, and persists one `HEAD`-bound `session.lastGate` measurement object (`headSha`, `treeSha`, `specHash`, `adrHashes`, `diffCoveragePct`, `mutationPct`, `policySource`, `pendingExemptions`, `modules`, `passed`).
2. **Fail-Closed Polyglot Per-Line Diff Coverage, Freshness & Vendored Engine Scope (`ADR-028`)**: Coverage and mutation reports whose `mtimeMs` predates execution start fail closed (`staleReport`). `parseCoverageReport` evaluates exact changed-hunk line hits across LCOV (`lcov.info`), Cobertura XML (`coverage.xml`), JaCoCo XML (`jacoco.xml`), and Go `cover.out`, failing closed on summary-only formats (`coverage-summary.json`, `jacoco.csv`) whenever modified source files are evaluated against a numeric `diffCoverage` threshold. Changed production source files missing from the coverage report count executable lines as `0%` covered (`uncoveredSourceFiles`). In non-owner adopting repositories (`!isEngineOwnerRepo`), vendored `.agent/scripts/**` files are excluded from diff coverage and default/unmutated Stryker scope (while remaining governed by `GATE_POLICY_DRIFT` ADRs and diff secret scanning).
3. **Diff-Scoped Mutation, Incremental Cache & Stable Exemptions (`ADR-021`, `ADR-028`)**: Stryker runs scope `--mutate` to changed source files (`--full` forces full module mutation). `gate --no-cache` bypasses `gate-cache.json` while preserving Stryker's content-hashed incremental file; `--force-mutation` (or `mutation --force`) passes Stryker `--force` explicitly. Changed trackable source files outside effective `mutate` globs fail closed (`diff-unmutated-sources`), zero-mutant results on non-empty code diffs fail closed unless the diff contains no executable source mutations, and exemptions match stable `<mutatorName>@<line>:<col>#<sha256(replacement)[0:8]>` identities from base config only.
4. **Diff Secret Scanning**: Added diff lines are scanned against high-confidence credential patterns (`ghp_`, `github_pat_`, `AKIA`, `sk_live_`, PEM private keys, Slack tokens) before passing the gate.
5. **Two-Axis Pointer Review & PR Evidence (`buildReviewPlan` & `buildPrSummary`)**: In `code` mode, `buildReviewPlan` always emits two orthogonal cold reviewer briefs backed by repo context pointers (`PRODUCT.md`, `docs/specs/*`, `docs/adr/*`, `GLOSSARY.md`, `CONTRIBUTING.md`, session `issueId`): **Spec Fidelity & Peer Reviewer** and **Architecture & Security Reviewer**. `buildPrSummary` (`sealit pr-body`) emits compact changed-module structure, measured gate proof, and mechanical `One-Way` vs. `Two-Way` merge-danger classification.

## 3. Outputs & Acceptance Criteria
- `sealit gate` exits `0` only when drift, ring boundaries, secret scan, lint, build, tests, diff coverage, and diff mutation all pass.
